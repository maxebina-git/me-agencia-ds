# 001 — Publicação DS: validação antes do npm publish

## Regra
Nunca publicar (`npm version patch` + `npm publish`) sem antes validar visualmente no `dev` do DS (`npm run dev`) que o componente alterado funciona como esperado no hero/live-preview.

## Processo
1. Ajustar componente (`src/components/OceanBackground.tsx` etc.).
2. `npm run build:lib` (build limpo).
3. `npm run dev` → verificar `HeroSection` e `Live Preview` (App.tsx) visualmente.
4. Confirmar com o usuário (resposta "sim" explícita) antes de `npm version patch` + `npm publish`. Nenhuma publicação automática.
5. No LP (`me-agencia-lp`), atualizar via `npm install @maxebina/max-ds@X.Y.Z --legacy-peer-deps` apenas após aprovação.

## Registro
- `v1.0.7`: publicado sem validação visual completa (erro: animação do oceano não confirmada em dev).
- Correção aplicada: reset de scroll, câmera inicial `y=30`, céus escuros, raios suaves.
- Próximo passo: validar `dev` do DS antes de `v1.0.9`.

# 002 — Ajustes e Melhorias no HeroSection e Propagação para Consumidores

## Contexto
O componente `HeroSection` no DS (`me-agencia-ds/src/components/HeroSection.tsx`) possuía uma prop `eyebrow` com valor padrão `'Tecnologia que gera resultado'`, que renderizava um badge acima do headline. No Live Preview do DS (`src/App.tsx`) e no consumidor `me-agencia-lp`, esse badge estava aparecendo indesejadamente, pois a prop `eyebrow` era passada como string vazia (`""`) para ocultá-la, mas o componente a tratava como truthy, exibindo um badge vazio.

Além disso, as props `subheadline` e `ctaSecondary` eram obrigatórias, limitando a flexibilidade para criar heroes com apenas um CTA.

## Decisão

### 1. Ajuste no HeroSection (`src/components/HeroSection.tsx`)
- Tornar `eyebrow` opcional e aceitar apenas strings não vazias para renderizar o badge:
  ```tsx
  eyebrow?: React.ReactNode;
  // Renderiza badge apenas se: typeof eyebrow === 'string' && eyebrow.trim().length > 0
  ```
- Tornar `subheadline` e `ctaSecondary` opcionais (não renderizam quando omitidas).
- Ajustar o default de `eyebrow` para `undefined` em vez de `'Tecnologia que gera resultado'`.

### 2. Atualização do PreviewSection (`src/App.tsx`)
- Passar explicitamente `eyebrow=""` no `<HeroSection>` do PreviewSection para garantir que o badge não apareça no Live Preview do DS.

### 3. Atualização do CHANGELOG.md
- Registrar as alterações na seção `[Unreleased]` → `Alterado` e `Corrigido`.

### 3. Build e Publicação
- Executar `npm run build:lib` para gerar `dist/` atualizado.
- Executar `npm version patch` → `1.0.15` (após validação).
- `npm publish` para publicar a nova versão no npm.

## Consequências
- **Prós**: HeroSection flexível, badge controlável via prop, CTA único possível, preview reflete fielmente o consumidor.
- **Contras**: Necessário atualizar consumidores que dependiam do comportamento antigo (nenhum impacto esperado, pois eram comportamentos indesejados).
- **Risco**: Nenhum, mudanças são backward-compatible (props opcionais).
